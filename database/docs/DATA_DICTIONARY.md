# Data Dictionary

## Phase 7–12 additions

The original Phase 2 definitions below remain historical baseline. Migrations 005–007 add:

| Entity | New fields / constraints |
| --- | --- |
| `disruptions` | `analysis_status` (PENDING, PROCESSING, COMPLETED, FAILED), `analyzed_at`; exactly one track/station target |
| `train_journeys` | `active_route` JSONB ordered station-code array for an applied reroute |
| `tracks` | `geometry_distance_km` generated from geodesic line length; operational `distance_km` remains separate |
| `route_recommendations` | Composite affected-journey/disruption FK, route array checks, one APPLIED recommendation per journey |
| `event_log` | `event_sequence` unique monotonic sequence, `attempts`, `available_at`, `locked_at`, UUID `lock_token`, `last_error` |
| `journey_status_history` | UUID id, journey FK, old/new journey status, changed_at, changed_by, reason |
| `logic_artifacts` | filename primary key, SHA-256 checksum, applied_at |
| `event_type` | Adds TRAIN_AFFECTED, JOURNEY_STATUS_CHANGED, NETWORK_CHANGED |

All tables enable RLS with explicit server-only policies for `railway_app`. See `PHASES_7_9_DESIGN.md` for triggers, units, integrity rules and synchronization semantics.

This document defines planned tables, columns, keys, constraints, and enum values. It is the source document for Phase 3 migrations.

## Table: `tracks`

Purpose: Stores operational track segments between stations.

| Column | Type | Key | Nullable | Constraints / Notes |
| --- | --- | --- | --- | --- |
| `id` | `uuid` | PK | no | Generated by database. |
| `from_station_id` | `uuid` | FK | no | References `stations.id`. |
| `to_station_id` | `uuid` | FK | no | References `stations.id`. |
| `region_id` | `uuid` | FK | no | References `regions.id`. |
| `distance_km` | `numeric(8,2)` |  | no | Must be greater than 0. |
| `track_type` | `text` |  | no | Example: `SINGLE`, `DOUBLE`, `ELECTRIFIED`. |
| `speed_limit_kmph` | `integer` |  | no | Must be greater than 0. |
| `status` | `track_status` |  | no | Default `ACTIVE`. |
| `geom` | `geography(LineString,4326)` |  | no | Spatial track line. |
| `valid_from` | `timestamptz` |  | no | Availability start. |
| `valid_to` | `timestamptz` |  | yes | Availability end, null means current. |
| `created_at` | `timestamptz` |  | no | Default current timestamp. |
| `updated_at` | `timestamptz` |  | no | Default current timestamp. |

Constraints:

- `from_station_id <> to_station_id`
- `(from_station_id, to_station_id)` should be unique for a current active segment unless multiple parallel tracks are intentionally modeled later.
- `valid_to is null or valid_to > valid_from`

## History Tables

History tables are append-only.

### `track_status_history`

| Column | Type | Key | Nullable | Notes |
| --- | --- | --- | --- | --- |
| `id` | `uuid` | PK | no | Generated by database. |
| `track_id` | `uuid` | FK | no | References `tracks.id`. |
| `old_status` | `track_status` |  | yes | Null for initial record. |
| `new_status` | `track_status` |  | no | New status. |
| `changed_at` | `timestamptz` |  | no | Change timestamp. |
| `changed_by` | `text` |  | yes | Operator/system. |
| `reason` | `text` |  | yes | Optional reason. |

### `train_status_history`

Same pattern as `track_status_history`, with `train_id`, `old_status`, and `new_status`.

### `journey_delay_history`

Stores `train_journey_id`, old delay, new delay, reason, and `changed_at`.

### `disruption_history`

Stores `disruption_id`, old status, new status, note, and `changed_at`.
